# 公众号参考样式：楷体红 v1

参考来源：[金融风控建模之数据有效性分析](https://mp.weixin.qq.com/s/z-XzPniWyzlyhh8gJAqwjA)。2026-11-03 读取原文 DOM、内联样式和 390px 浏览器计算样式，并对照手机宽度截图。主题只复现排版语言，示例正文为新写内容，不复制原文或报告图片。

## 样式分析

| 元素       | 原文观察                                                                         | 本地实现                                                                |
| ---------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 主色       | 深红 `#c00000`，部分阴影为 `#ff0000`                                             | 固定深红章节、红色细线与强调段                                          |
| 正文       | 主要为楷体 / 楷体\_GB2312 / SimKai、14px、`#262626`                              | 14px 楷体优先字体栈，支持在完整样式设置中调整                           |
| 行距与缩进 | 常规正文主要为 22.4px 行高，段首 34px；个别段落使用 1.5px 字距                   | 正文行高 1.6、段首 34px，常规字距 0.544px；引言保留 1.5px 字距          |
| 引言       | 红色顶线、白底红字标签、浅粉底 `#fcf2f2`，内边距 10px                            | `WeChatIntroV1`；段落 14px、1.75 行高、28px 缩进                        |
| 二级章节   | 25px 红色数字块、无边框文字与独立的带红影细线；补充截图要求横线铺满正文宽度      | Markdown `##` 自动生成；编号靠左、文字水平与垂直居中、独立底线铺满；首章从“零”开始，也支持显式编号 |
| 三级章节   | 宽度约 35%，靠左；01/02 编号、较粗数字下划线和细标题下划线                       | Markdown `###` 自动生成，进入新章节后重新编号                           |
| 四级标题   | 补充截图：红色小方块与深色楷体标题                                               | Markdown `####` 自动生成 6px 深红方块，标题 14px、加粗、1.5px 字距       |
| 代码块     | Atom One Light；`#fafafa` 浅底、`#383a42` 文本、12px 等宽字；高亮 span 行高 26px | 本地 `atom-one-light` 配色，26px 代码行距、5px 圆角；阴影使用当前主色的 28% 透明度 |
| Mac 标题栏 | 三个圆点，原文使用远程 SVG 背景                                                  | 用三个真实 span 和内联颜色绘制，不依赖远端图片                          |
| 报表与宽表 | 复杂图表以图片呈现；正文没有原生 HTML 表格                                       | `WeChatFigureV1` 插入作者自己的报告图片；另附浅粉表头的原生表格配套样式 |
| 开篇图文   | 图片浅灰边框与轻阴影，底部紧接窄主题色标语条                                    | `WeChatFigureBannerV1`；图文间距 4px，14px 正文时标语为 12px / 1.6，纵向内边距 2px |

原文存在少量混合字号、缩进和字距。本主题选择其主要参数作为可长期复用的规范，避免把历史编辑产生的偶然差异固化。网页上方由微信提供的文章标题、作者栏和底部互动栏由平台控制，不纳入正文主题。示例中的正文 h1、原生表格和引用为配套扩展。

## 使用

1. 打开编辑器顶部「成稿检查 → 主题与代码」。
2. 选择「公众号·楷体红」。
3. 点击「新建同款排版示例」新增示例文章，当前文章不会被替换。
4. 二、三、四级标题直接使用 Markdown；例如 `#### 特征区分度` 显示红色小方块标题。引言、红底短句、红色强调和报告图片可从「固定组件」插入。
5. 在「公众号成稿」中选择手机宽度，检查实际 HTML，再复制、导出或同步到草稿。

所有组件现在统一跟随当前主题配色、字体和字号，并使用直角边框。旧组件名称和内容属性保持可用；缩略图与正文采用同一适配规则。额外自定义 CSS 仍可覆盖预设，验收时应使用相同配置。

开篇的图片和底部标语可用一个组件插入：

```md
<WeChatFigureBannerV1 src="https://raw.githubusercontent.com/hengshu-credit/hscredit/main/docs/assets/readme/showcase/intro-strategy.png" text="用数据检验观点，用代码记录方法" alt="策略上线报告" />
```

`src` 和 `text` 为必填属性，`alt` 为图片替代说明。组件位于工具栏「组件 → 图片与标语」和「成稿检查 → 固定组件」。图片保持原始比例，不裁切；浅灰边框与轻阴影独立于主题色，标语颜色和字体跟随当前主题。

已有文章无需改写：相邻的 `WeChatFigureV1` 与 `WeChatBannerV1` 会自动收紧为相同的 4px 间距。`caption=""` 不再生成空图注；非空图注仍然保留。两个组件中间有正文时，各自保留正常段间距。

## 一致性实现

- 章节数字和四级标题的小方块是渲染管线生成的真实节点，不使用 CSS 计数器、伪元素或 3D 变换。二、三级标题使用内联的 table/table-cell 布局；二级标题占满正文宽度，三级标题按内容宽度排列，长标题在正文宽度内换行；编号单独包裹，避免随多行标题拉高。
- 二级标题按参考文章 `//*[@id="js_content"]/section/section/section/section[5]` 的结构，将无边框、无阴影的文字与底线分开。文字行高与编号块同为 25px，编号单元格扣除底线的 1px 后垂直居中；阴影仅施加在底线上。底线保留一个 `<br>`，避免完全空节点在微信中被清除。三级标题继续使用文字单元格的底边框；两者均不依赖 `max-content` 与 flex 收缩计算。
- 本地即时预览和成稿生成共用装饰函数。复制、HTML 导出和 COSE 正文继续使用统一的成稿产物。
- 字体、正文参数、代码高亮、引言和装饰均内联到 HTML。Mac 圆点不依赖原文的远程 SVG。
- 参考主题的独立成稿使用 20px 页面边距与 10px 正文内边距，对齐原文在 390px 屏幕下的主要内容宽度。

浏览器已核对本地与隔离成稿中的正文字体、14px 字号、22.4px 行高、34px 缩进、引言 24.5px 行高，以及代码 12px / 26px 的计算样式一致。成稿不依赖外部 CSS 或 SVG。

2026-11-09 只读检查用户提供的微信临时预览，确认旧标题的空下划线节点被清除，短标题在 flex / max-content 布局下换成两行。使用新标题 HTML 在该页面的本地 DOM 副本中验证，保留微信页面 CSS 并模拟 `span[leaf]` 文本包装：WebKit 下 320、375、390、430px 的 21 个二、三级标题均未越界，短标题保持一行，编号块高度保持 25px。Chrome 和 WebKit 的隔离成稿另覆盖长中英文标题、显式编号、字体回退及清除类名和空节点的场景。此验证没有写入微信草稿；重新粘贴后的平台清洗仍需通过新的手机预览验收。

同日根据补充截图将二级标题铺满，并按指定参考节点拆分文字与底线。WebKit 手机宽度检查中，文字中心与 25px 编号块中心偏差为 0px，文字及其容器无边框、无阴影。新组合组件与旧相邻组件的图文间距均为 4px；图片不继承正文图片外边距，也不受缩略图页面的高度上限裁切。

真实公众号草稿尚未在账号中验收。字体由阅读设备决定：未安装楷体或兼容字体时会回退；公众号也可能清洗样式、转存图片并适配深色模式。因此可保证本地交付 HTML 的一致性，不能在没有实际草稿和手机预览的情况下承诺所有设备的像素级相同。以图片导出的报表保留自身字体和配色，但正文保留可选择、可复制文本。
