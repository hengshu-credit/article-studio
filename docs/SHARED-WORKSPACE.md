# 共享文章与外网部署

所有客户端连接同一个 Article Studio 服务，使用同一个工作区。正文、标题、文章层级、主题、字号、代码配色、自定义 CSS 和组件设置会同步。当前选中的文章、光标、深色模式、设备视图、图床凭据和 AI 密钥保留在各客户端。

## 操作与撤销

- 每次编辑器内容变更或一次文章库操作，提交为一个全局操作；同一轮界面更新中的相关字段一起提交。
- 服务端按收到操作的顺序执行并推送完整状态。同一字段后到的修改生效，其他字段的修改保留。没有版本校验、版本选择或冲突确认。
- 任何客户端的撤销按钮和 Ctrl/Cmd+Z 都撤销全局最近一步。例如 A 改正文、B 改标题，C 撤销时先恢复标题，再撤销时恢复正文。
- 重做按钮、Ctrl/Cmd+Shift+Z 和 Ctrl/Cmd+Y 使用同一个全局重做栈。撤销后有新修改时清空重做栈。
- 撤销/重做正文会在发起操作的窗口打开对应文章，滚动到并选中改变的文字；删除时定位到删除位置。其他窗口同步正文并保留自己的光标位置。
- 默认设置回填、按需加载样式商店和重复保存回执不作为新编辑，不会清空重做记录。没有可用历史时，工具栏的对应按钮禁用。
- 远端更新、本地缓存写入、重连及相同请求的重试都不会产生额外的撤销步骤。文章与撤销栈一起持久化，服务重启后仍可撤销。
- 内部消息序号只用于避免较早的网络响应覆盖较新的消息，不是文章版本，也不阻止任何客户端提交操作。
- 同时编辑同一正文时，最后到达服务端的正文生效；不会逐字符合并两端输入。需要恢复前一操作时使用全局撤销。

底部显示「多端已同步」「正在同步」或断线状态。断线期间操作在当前标签页暂存，重连后重试；刷新同一标签页也会恢复待发队列。关闭标签页前请等待「多端已同步」，避免丢失尚未送达服务端的操作。

## 数据位置与迁移

默认数据库位于仓库根目录 `data/workspace.sqlite`，已从 Git 排除。可通过 `ARTICLE_STUDIO_DATA_PATH` 指向服务器上的持久目录。SQLite 使用 WAL；备份时先停止服务，再备份整个数据目录。不要让多个 Article Studio 进程同时操作同一个数据库，否则不同进程间没有实时广播。

第一次连接尚未初始化的服务时，将首个浏览器的文章和排版设置导入服务器。已有工作区（包括用户删除所有文章后的空工作区）不会被后来的客户端覆盖。浏览器接入前的文章存为 IndexedDB `doocs-md` 的 `settings` 中 `article-studio-before-shared-sync`，不上传该备份。需要导入其他浏览器的旧文章时，先导出 Markdown，再在共享工作区导入。

### 素材库

共享模式的图片统一进入素材库：编辑区粘贴/拖入图片、素材库多选/拖入/粘贴上传、导入文章时上传的本地图片，以及新生成的 AI 图片都走同一入库流程。现有文章中的旧图片链接不会被后台批量抓取；粘贴的网络图片会尝试下载入库，遇到跨域限制时显示错误，可以下载后再上传。

- 打开工具栏「素材库」，按名称搜索，选择缩略图查看原图，再点「插入正文」。其他在线客户端打开的素材库自动更新。
- 每张图片支持 PNG、JPEG、GIF、WebP，原文件不超过 10 MB，最多 4000 万像素。保留原图，不自动缩小文字截图或改变 GIF 动画；自动生成最大 480 × 360 的 WebP 缩略图供列表使用。
- 去重以原文件字节的 SHA-256 为准，不依赖文件名。上传前向服务器查询，已存在时直接引用，不再传输图片正文；并发请求在服务端也只保存一份。改变编码或压缩质量后的文件视为不同素材。重复上传保留首次入库的名称。
- 素材信息保存在 SQLite 的 `materials` 表，原图和缩略图保存在数据库文件同级的 `materials/` 目录。默认是仓库的 `data/materials/`。目录已经被 Git 忽略。
- 文章只保存稳定的 `/media/<hash>.<ext>` 地址，图片字节不会随正文写入 SQLite 撤销快照。插入图片可全局撤销/重做，素材文件继续保留，避免其他文章或重做引用失效。
- 素材列表、上传接口和原图读取都沿用服务端登录保护，不额外公开图片。统一成稿在生成公众号预览、复制、HTML 导出和 COSE 内容时内嵌素材图片；图片缺失则明确报错，不输出损坏成稿。实际平台是否完成图片转存仍需在草稿中核验。

备份必须包含数据库和同级 `materials/` 目录；只导出 Markdown 不会打包图片文件。文章同步请求上限仍为 16 MB，单张图片上传单独限制为 10 MB。

## 本地运行

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

访问 `http://127.0.0.1:5173/`。两个独立浏览器访问这个地址即可测试文章同步和跨端撤销。浏览器扩展和 uTools 继续使用原有本地存储。

需要暂时使用原有独立浏览器模式时，在启动前设置 `$env:ARTICLE_STUDIO_LOCAL_ONLY = '1'`。默认共享模式的网页构建需要由配套服务或 `pnpm preview` 承载，不能直接上传到纯静态空间。

## 外网部署

当前尚未绑定实际域名或服务器。准备服务器时采用一个 Node 服务进程、一个持久数据目录，以及 HTTPS 反向代理。

1. 安装 Node.js >= 22.22.2 和 pnpm 11.25.0，上传或拉取项目。
2. 执行 `pnpm install --frozen-lockfile`、`pnpm build`。
3. 设置以下服务端环境变量，使用系统服务或进程管理器运行 `pnpm serve`。

| 环境变量 | 含义 |
| --- | --- |
| `ARTICLE_STUDIO_USER` | 共享工作区登录名，默认 `studio` |
| `ARTICLE_STUDIO_PASSWORD` | 必填，至少 12 位；使用自己生成的随机长密码 |
| `ARTICLE_STUDIO_DATA_PATH` | 数据库绝对路径，例如 `/var/lib/article-studio/workspace.sqlite` |
| `HOST` | 默认 `127.0.0.1`，由同机反向代理访问 |
| `PORT` | 默认 `5173` |

生产入口同时保护网页、接口和事件推送。浏览器首次打开时使用 HTTP Basic 登录框输入共享工作区账号。所有设备用同一账号，登录成功后即进入同一工作区。密码放在服务端环境或权限受控的环境文件中，不写入前端 `VITE_*` 配置或 Git。

4. 将域名的 DNS 解析到服务器，以 HTTPS 反向代理到 `127.0.0.1:5173`。例如 Caddy 配置：

```caddyfile
write.example.com {
    reverse_proxy 127.0.0.1:5173
}
```

将示例域名替换为自己的域名。反向代理需保留 Host 和 Authorization，并允许 `/api/workspace/events` 的长连接及时发送数据；不要缓存 `/api/workspace*`。公网只暴露 HTTPS 入口，开发服务器不用于公网部署。反向代理参考：[Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。

5. 使用两个独立浏览器或手机与电脑登录：A 修改、B 检查；B 撤销、A 检查；刷新和服务重启后再次检查内容及撤销。定期备份持久数据目录。

自定义域名的 COSE 分发还需将最终域名加入扩展桥接的受信任来源；当前仍保留原有本机与上游域名白名单。域名确定后再配置，不向所有网站开放扩展权限。

## 验证

```powershell
pnpm test:workspace
pnpm test
pnpm typecheck
pnpm build:all
```

自动化验证覆盖双 SSE 客户端、跨端全局撤销与重做、字段到达顺序、新增删除与层级恢复、排版撤销、断线重连、消息乱序、待发操作恢复、重复请求去重、数据库重启恢复及跨站写入拒绝。
